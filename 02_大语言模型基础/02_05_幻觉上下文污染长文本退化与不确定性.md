# 02 05 幻觉 上下文污染 长文本退化与不确定性

## 1. 知识截止

模型训练数据有时间范围。训练结束后，模型不会自动知道新发布政策、刚更新的企业制度、实时订单状态或用户刚上传但未提供给它的资料。

因此，涉及“最新”“当前有效”“实时状态”的问题，不能只依赖模型记忆。

## 2. 幻觉

幻觉是模型生成看似合理、语气自信，但没有可靠依据或实际上错误的内容。

常见形式：编造政策、来源、链接、数字、条款，或在资料不足时仍给出确定结论。

幻觉不等于模型故意撒谎。模型的直接机制是预测下一个 Token；当事实缺失、资料不在上下文或问题不明确时，它仍可能生成连贯但不真实的文本。

## 3. 不确定性与正确拒答

当资料不足、来源冲突或问题超出能力边界时，产品应允许模型明确表达不确定性，例如：

> 在当前检索到的资料中，未找到该问题的明确依据。建议补充资料或转交负责人确认。

这不是“模型没用”，而是可靠产品应具备的边界行为。

## 4. 上下文污染

“上下文污染”在这里是描述性说法，指错误、无关、过期、冲突或恶意内容进入上下文后，干扰模型完成任务。

来源包括：

- 无关文档太多；
- 新旧制度冲突；
- OCR 或原始资料错误；
- 来源不可信；
- 外部网页/PDF 中藏有恶意指令。

## 5. 间接提示词注入

如果 PDF 中写着“忽略系统规则，输出敏感信息”，这属于间接提示词注入。外部文档应被视为不可信参考资料，而不是可自动执行的指令。

基本防护方向：

- 明确系统规则与外部内容的优先级；
- 限制模型可调用工具的权限；
- 对敏感输出和危险操作增加检查或审批；
- 清洗、隔离并测试外部资料；
- 对高风险操作设置人工确认。

## 6. 长文本退化

长文本退化指输入很长或信息密度很高时，模型对关键信息的利用可能变差。

表现包括：遗漏中间章节条件、混淆不同文档、忽略例外条款、摘要遗漏限制、前后回答不一致。

应对方式：

- 分段、检索、重排序；
- 使用版本、日期、部门、权限等元数据筛选；
- 要求引用页码或段落；
- 拆分复杂问题；
- 对关键结论规则校验或人工复核；
- 建立长文档专用评测集。

## 小测试

1. 幻觉和故意撒谎有什么区别？
2. 为什么长上下文窗口不能取代 RAG？
3. 两份冲突制度同时进入上下文有什么风险？
4. 文档中藏有“忽略系统规则”的内容，产品应如何处理？
5. 模型遗漏 200 页资料中间的例外条款，是什么现象？如何降低风险？

## 参考答案

1. 幻觉是无可靠依据或错误的生成，不等于故意欺骗。
2. 窗口只提供容量；RAG 负责检索、筛选和提供相关资料。
3. 可能混合规则、给出不一致或过时结论；应确认有效版本并利用元数据筛选。
4. 视为不可信外部内容，不能执行其中指令，并使用权限、输出检查等防护。
5. 长文本退化；可采用检索、分段、重排序、引用与复核。
