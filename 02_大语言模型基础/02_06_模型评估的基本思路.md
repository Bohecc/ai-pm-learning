# 02 06 模型评估的基本思路

## 核心原则

AI 产品不能只依赖“感觉回答不错”。应先定义什么算好，再用代表性案例持续验证。

## 1. 评测集

评测集是一组经过挑选的问题、输入资料和预期标准，用于检查模型、Prompt、RAG 或工作流是否达到要求。

企业制度助手的评测集应覆盖：常见问题、模糊提问、长文档、需要来源的问题、资料缺失、过期政策、恶意指令和高风险边界案例。

只放简单常见题会让分数虚高，无法反映真实可靠性。

## 2. 常见评测维度

- 正确性：结论是否正确；
- 相关性：是否真正回答用户问题；
- 完整性：是否遗漏关键条件；
- 引用一致性：引用是否真实存在且支持结论；
- 格式合规性：JSON、表格或字段是否符合要求；
- 安全性：是否泄露信息、越权或给出危险建议；
- 延迟与成本：是否可接受。

## 3. 离线与线上评测

- 离线评测：上线前，用固定案例比较模型、Prompt、RAG 或流程变化。
- 线上评测：上线后，观察真实用户成功率、投诉、人工接管率、延迟和成本。

离线评测减少明显问题；线上评测发现真实世界中的新问题。

## 4. 人工 规则与模型辅助评测

| 方式 | 适合场景 | 局限 |
|---|---|---|
| 人工评测 | 高风险、复杂、需要专业判断 | 成本较高、速度较慢 |
| 规则评测 | JSON 解析、字段必填、格式检查 | 不能判断复杂事实正确性 |
| 模型辅助评测 | 大量初步评分、文本质量辅助判断 | 仍需抽检，不能盲信 |

成熟实践通常是三者组合。

## 小测试

1. 为什么评测集不能只放简单题？
2. “引用是否真实且支持结论”属于什么维度？
3. JSON 是否可解析、字段是否齐全，适合哪种评测？
4. 为什么上线后仍要持续监控？

## 参考答案

1. 会导致分数虚高，无法发现边界、风险和真实失败案例。
2. 引用一致性。
3. 规则评测。
4. 真实用户、资料与系统环境会产生离线测试未覆盖的问题。

## 验收标准

- [ ] 能为一个 AI 功能提出至少三类评测维度。
- [ ] 知道离线评测与线上监控都需要。
- [ ] 能区分人工、规则和模型辅助评测的用途。
