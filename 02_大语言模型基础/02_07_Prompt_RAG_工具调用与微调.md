# 02 07 Prompt RAG 工具调用与微调

## 为什么单独成节

这四种方案经常被混淆，但它们解决的问题不同。模型回答不好时，不应默认“去微调”。

## Prompt

Prompt 是每次调用模型时提供的任务说明、上下文、示例、约束和输出要求。

适合：任务描述不清、输出格式不稳定、需要特定语气/长度/示例或场景规则。

例：要求从投诉中提取问题类型、情绪和人工处理标记，并只输出 JSON。

## RAG

RAG（检索增强生成）是先从可靠资料中找相关内容，再把资料提供给模型回答。

适合：最新信息、企业内部知识、需要引用来源、资料持续更新的场景。

例：依据最新报销制度回答员工问题。

## 工具调用

工具调用让模型在受控条件下查询数据库、订单系统、搜索服务或其他 API。

适合：实时状态查询、计算、执行可授权操作。

例：查询订单目前位置。模型不应凭记忆回答实时订单状态。

## 微调

微调是在已有模型基础上用特定高质量样本继续训练，改变模型在某类任务上的行为模式。

适合：长期高频、标签稳定、已有大量高质量标注样本，且 Prompt 仍无法稳定满足要求的任务。

例：十万条人工审核过、标签体系稳定的客服工单分类。

## 先评测，再决定

如果团队只觉得“回答不好”，但没有失败案例、没有标准答案，也没有质量定义，第一步应是评测和问题分析，而不是立即选模型或微调。

## 快速判断表

| 问题 | 优先方案 |
|---|---|
| 输出格式或语气不稳定 | Prompt |
| 需要最新、私有、可引用资料 | RAG |
| 需要实时查询或执行外部动作 | 工具调用 |
| 重复任务且高质量样本充足 | 微调 |
| 不知道为什么效果差 | 先评测分析 |

## 小测试

1. 企业刚更新报销制度，助手应如何获取新规则？
2. 模型总在 JSON 后补解释，先改什么？
3. 用户询问订单实时位置，应使用什么？
4. 高质量标注样本很多、标签体系稳定而 Prompt 不稳定，可能考虑什么？

## 参考答案

1. RAG，基于新制度资料检索并引用。
2. Prompt 和结构化输出约束。
3. 工具调用查询订单系统。
4. 微调，但仍需评测成本与收益。
