# 02 08 第二章复盘与验收

## 一页复盘

### LLM 如何生成

文本 → Token → Embedding → Transformer 用 Attention 处理上下文关系 → 计算下一个 Token 的概率 → 重复生成回答。

### 训练与模型类型

- 预训练：学习语言模式和下一个 Token 预测；
- 指令微调：学习理解任务和按要求回答；
- 对齐：提高有帮助、安全、符合指令的倾向；
- 基础模型：训练底座；聊天模型：面向常见用户任务；推理模型：复杂多步任务可能更强。

### 选型

看任务质量、上下文窗口、成本、延迟、稳定性、多模态能力、工具能力和数据安全。不要只看参数规模或品牌。

### 事实与风险

- 模型不是数据库或搜索引擎；
- 幻觉是无可靠依据的生成，不等于故意撒谎；
- 最新/私有资料应通过 RAG、数据库或工具获取；
- 长上下文不等于可靠长文档理解；
- 外部文档中的指令可能构成间接提示词注入。

### 产品系统

- Prompt：任务说明与输出约束；
- RAG：找相关资料；
- 工具调用：查实时系统或执行受控动作；
- 微调：长期稳定重复任务的行为优化；
- Evals：证明系统是否达到要求。

## 参考答案要点

1. 根据已见内容预测并逐步生成下一个 Token。
2. 上下文容量、成本、速度。
3. 比较问题和资料的语义相似度，找相关资料。
4. 不等于；它是数学计算机制。
5. 前者学习语言模式，后者学习遵循任务和格式。
6. 还需考虑质量、成本、延迟、安全、上下文和稳定性。
7. 它只影响随机性，不能提供事实验证。
8. 模型结合权威、最新、可引用的检索或工具结果。
9. 幻觉是错误或无依据生成，不必然是故意欺骗。
10. RAG 找资料；窗口提供容量；元数据筛选版本、日期、权限和来源。
11. 间接提示词注入。
12. 分段、检索、重排序、引用、拆题、评测和复核。
13. 原文页码/位置核对、规则校验、异常处理和人工复核。
14. 见 02_07 的快速判断表。
15. 离线减少已知问题；线上发现真实使用环境中的新问题。

## 本章易错点

- RAG 不是 RLHF；RAG 是检索增强生成，RLHF 是对齐方法之一。
- Embedding 不等于检索；它是数字表示，检索是其常见应用之一。
- 基础模型不等于适合简单产品任务的聊天模型。
- 长上下文不等于长期记忆，也不等于自动可靠地利用全部资料。
- 结构化输出和规则校验能提高格式可靠性，但不能单独保证从原文提取的事实一定正确。
