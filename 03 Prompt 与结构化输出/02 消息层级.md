# 02 消息层级

## 通俗定义

- System：总体身份、长期规则和安全边界。
- Developer：产品业务规则、流程和输出要求。
- User：当前任务。
- Context：任务所需的材料、历史记录或工具结果。

## 为什么重要

消息分层有助于判断哪些规则长期稳定、哪些内容可被用户改变，以及哪些规则不能被用户指令覆盖。

## 产品案例

```text
System：不得编造事实。
Developer：输出必须包含结论、依据和待确认问题。
User：请分析这份政策文件。
Context：政策文件正文。
```

## 常见误区

- 用户的具体说法不一定能覆盖更高层级规则。
- Context 是材料，不等于规则。
- Developer 指令不能替代真正的权限系统。

## 小测试

判断四句话的类型：角色与事实边界、固定输出字段、当前分析请求、政策正文。

## 参考答案

依次是 System、Developer、User、Context。
