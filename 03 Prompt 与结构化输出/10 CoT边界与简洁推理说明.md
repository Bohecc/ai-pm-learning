# 10 CoT 的边界与简洁推理说明

## 通俗定义

复杂任务可以分步骤处理，但产品通常应要求模型输出可验证的结论、依据、简要判断和待确认问题，而不是要求展示完整内部思维过程。

## 为什么重要

结构化的简洁说明便于用户复核、降低冗长输出和成本，也避免把“写得很详细”误认为“结论一定正确”。

## 产品案例

```json
{
  "结论": "文件要求项目经过多级审批",
  "依据": ["第 12 页提到街道、区级和市级审核"],
  "关键判断": "该结论直接来自文件",
  "待确认问题": ["文件未说明各级审批时限"]
}
```

## 常见误区

- 解释依据不等于完整思维链。
- 所有任务都不需要复杂推理。
- 详细输出不等于真实或正确。

## 小测试

在“展示完整内部思维过程”和“输出结论、依据、待确认问题”中选择更适合产品的要求。

## 参考答案

后者更适合，因为它提供可验证信息，简洁、可控、易于验收。
