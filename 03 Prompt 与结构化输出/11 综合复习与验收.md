# 11 综合复习与验收答案

## 综合能力标准

学完本章后，应能：

1. 把模糊需求改写为目标、上下文、约束和输出格式。
2. 区分 System、Developer、User 和 Context。
3. 用正例、反例和边界案例定义任务边界。
4. 把复杂任务拆成可验收步骤。
5. 设计字段、类型、枚举、必填项和 `null` 规则。
6. 进行 Prompt 版本管理和回归测试。
7. 判断哪些问题应交给检索、权限、工具验证或人工处理。
8. 要求输出结论、依据和待确认项，而不是完整内部思维过程。

## 综合产品示例

```text
功能名称：建筑设计作业初步分析助手
目标用户：建筑学专业大学生
用户问题：上传设计任务书和场地资料后，快速了解设计要求、限制条件、规范依据和待确认事项。
```

### Prompt 核心规则

1. 提取功能需求、面积要求、场地条件和限制。
2. 区分明确事实、合理推断和待确认问题。
3. 只依据上传资料和指定规范来源，不编造规范内容。
4. 信息不足时输出 `null` 或“待确认”。
5. 不替代教师、建筑师或专业审查人员做最终判断。

### 输出字段

项目目标、功能需求、场地限制、规范依据、初步设计建议、原文证据、待确认问题、是否需要人工复核。

### 验收案例

- 正常：资料包含面积、功能和场地信息，系统能正确提取并附证据。
- 异常：缺少用地面积或规范来源，系统不得猜测，应标记待确认。

### 人工介入条件

涉及消防、结构安全、法规合规、资料冲突或高风险设计判断时，必须转人工复核。
